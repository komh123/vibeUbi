消除靠記得

這不是一個更便宜的自動測試。它解決的是一個結構問題：在一個沒有人——也沒有任何 agent——記得住全貌的專案裡，覆蓋率會安靜地衰減。 功能會、資安曝露面也會。每一條規則背後都有一個具名的事故，而每個事故的形狀都一樣： 有人本來應該記得，然後沒有。

I

兩個目標其實是一個，但只有一個方向成立

目標一 · 成本

「人工測試越來越貴，所以要自動化。」

把測試從人手上移到機器上，單次成本下降。但「要測什麼」還留在人腦裡—— 第 847 個功能上線時，沒有任何機制會說它沒有測試。自動化降低了單價，沒有阻止覆蓋率衰減。

目標二 · 記憶

「覆蓋率是一個記憶產物，而記憶不隨專案規模擴張。」

人記得的不是「所有存在的東西」，是「最近碰過的東西」。所以覆蓋率其實是 誰剛好想起什麼的函數。把「要記得」逐一換成「系統自己知道」，成本會順帶下降。

目標二包含目標一，反過來不成立。 2026-09-02 起文件功能中斷兩天，GET /api/agent-next/docs 全程回 200 {"docs":[]}（傳輸失敗被摺成「這個使用者沒有文件」），閘門一次都沒點名。 那兩天的代價不是用測試機器的分鐘數計價的。

兩個目標會互相拉扯，產品必須選邊

為成本最佳化會讓你少跑；為記憶最佳化會讓你永遠全跑。 這裡選的是：把全跑做到便宜到負擔得起，而不是把全跑做成選擇性的。 真的要縮範圍時，縮的範圍會被寫進報告與名冊——縮範圍是一個被記錄的決定，不是預設。

為什麼 AI 寫碼讓這件事從「好習慣」變成「必要基礎設施」

  • 程式碼產出速度超過心智模型的更新速度。新頁面、新 route、新 tool、新對外監聽埠的增加率，早就超過任何人能持有的清單。
  • 作者本身完全沒有記憶。新的 agent session 對上週自己寫了什麼是零回憶。「靠記得」對人只是不可靠，對 agent 是結構上不存在。
  • 寫的跟審的是同一個模型，盲點是相關的。忘了接測試的那個 agent，就是等一下「review」時不會發現的那個。
  • agent 會高頻率製造「看起來綠」的失敗。agent 對「指令成功了」最佳化，而 exit 0 是它最容易達成的東西。
II

點名：十種靠記得，與拿掉它的那行程式

每一列的標記不是流水號，是取代那個記憶的函式名字。這不是流程，是名冊——順序不帶資訊，缺席才帶。

要記得 01這個功能存在
discover/* → no-orphans 從樹上讀出每個 page / api route / view / nav 列 / slash command / agent tool。 發現到但沒宣告 = orphan = 測試紅。宣告過但樹上沒了 = stale，一樣紅。
沒有它的樣子 新功能上線，零測試，而且沒有任何東西會提。一年後沒人說得出哪些功能從來沒被驗過。
要記得 02去跑那個檢查
SHIP_STEPS 閘門不是一個你可以選擇呼叫的工具，它是部署路徑本身。swap 之後必然接 sweep 接 gate。
命名這套系統的那次事故 引擎切換那天被切了四次、壞了三次，每次都是事後手動跑一層才抓到。「那個做法有效的前提是有人記得。」
要記得 03這個測試有被誰叫到
check:test-coverage 沒有任何 script 指名的測試檔，等於不存在。基線寫進 repo，新增的測試落在所有閘門套件之外就紅並點名它。
2026-09-09 · 一天三次 三次都是「測試存在、閘門沒叫它」。量出來是 941 個測試檔裡 214 個沒有任何閘門會叫。
要記得 04綠燈不等於驗到了東西
testRanVerdict 對每個宣稱自己是測試的步驟，除了退出碼再問一句：輸出裡有沒有 # pass N，而且 N > 0。
同一種形狀咬了三次 執行檔路徑不存在 → # pass 0 + exit 0；測試套件停在第 44 個檔案而後面 460 個從沒跑過； eslint 用了不存在的 formatter，exit 2、零行輸出，被讀成「0 個問題」。「沒有壞消息」被當成「有好消息」。
要記得 05部署真的生效了
deployProof 唯一接受的證據：線上服務吐出的頁面引用了剛放進去那個 build 的 id。 不信 build 的退出碼、不信 restart 的回傳、不信 HTTP 200、不信自己的報告。
它被命名的那次失敗 restart 回 0，而換版沒有生效。除了這一條以外，每一個訊號都說部署成功了。
要記得 06工作樹跟剛才驗的是同一棵
treeDrift 內容雜湊，算一次 3.8 秒。問的不是「乾不乾淨」（這棵樹永遠是髒的），是「跟五分鐘前一不一樣」。
2026-09-09 一個 session 在 verify 跑著的時候繼續編輯檔案，而 verify 早就過了那一步。 那次是自己想起來才停掉重跑的——這個洞唯一的守衛就是「有沒有人剛好想起來」。
要記得 07設定送到了真正讀它的那個行程
envParity 某個 key 出現在消費端的原始碼裡、主設定檔給了非空值，而消費端自己的 env 檔沒有它或給空字串 → 紅。
2026-09-09 · 同一天兩次 五個租戶「已經搬完並隔離」，檔案複製了、雜湊驗過了、清單也改了，而執行時每個租戶仍解析到共用 bucket。 隔離一天都沒有發生過，而每一個閘門都是綠的。
要記得 08那一層當初為什麼被跳過
--without + --without-reason 跳過一層是一個決定，所以必須寫下來，理由跟著層一起進名冊。 prereqVerdict 更狠：層跑不起來是硬停，不是靜默 skip。
它防的是一個更糟的可能 缺一個瀏覽器 → 那層答不出來 → 閘門把錯誤當阻擋 → 回滾一個完全健康的部署。 管線會用一個工具缺口製造出一場事故，而且是在動了正式環境兩次之後。
要記得 09把測試在線上建的東西清掉
reapDecision run-scoped 名字；開跑前先收上一輪的屍，四個條件缺一不刪、任何不確定都 fail closed； 清不掉就是紅格並點名那個物件，永遠不是沉默。
為什麼非得在線上建東西 唯讀的層只會讀。在這一層之前，這個產品的每一條建立路徑從來沒有被閘門走過一次—— 那正是上面那兩天文件中斷躲過所有檢查的原因。
要記得 10這個紅是不是這次部署造成的
attributedVerdict 閘門的全部正當性是「撤銷部署會撤銷問題」。所以 P0 紅格重驗一次： 撐過重驗 → 這次部署認帳，回滾；重驗過了 → 免責，但照樣報出來。
一次被冤枉的回滾 一個版本被正好一格這種紅撤掉了——事後對著還原回去的 build 量，同一個檢查三次跑出 124 秒（紅）、7 秒、28 秒。解法不是把期限拉長：一個綁在回滾上的擲硬幣， 比沒有閘門更糟，因為它教人「重跑到綠為止」。
P0 fail ─ 回滾 error ─ 回滾 新的 HIGH 資安發現 ─ 回滾 P1/P2 fail ─ 報出不擋 blocked ─ 報出不擋 baseline 內的已知資安債 ─ 報出不擋 skip ─ 要有理由 pass

判決詞彙依會不會擋部署上色，不依名字聽起來多嚴重。 error 跟 P0 fail 同色，因為一個答不出來的層，對剛部署上去的東西而言不是通過。 blocked 跟已知資安債同色：回滾碰不到一個掛掉的外部依賴，也修不好三個月前就存在的漏洞—— 但兩者永遠會被說出來，「安靜放行」會教人這一層是裝飾品。

III

把記憶換成結構，只有三種換法

十種靠記得，全部是這三條的實例。這三條就是產品的公理，而且它們是分層的—— 存在、意義、結果。功能是這樣，資安也是同一套（每格底下的第二行）。

發現取代記憶

系統自己從樹上、從機器上找出「有什麼」。忘記變成不可能，因為沒有人需要記。

B

宣告取代記憶

該記的東西寫進檔案一次，而缺席本身就是錯誤。記憶從腦子搬到一個有測試在讀的檔案裡。

適用於意義：這是什麼、誰該看得到、多重要、怎麼算通過。

C

證據取代記憶

永遠不信「成功了」的回報，只信一個從外部獨立觀察得到的事實。因為「記得要懷疑」本身也是一種記憶任務。

適用於結果。

deployProof · testRanVerdict
treeDrift · envParity
attributedVerdict 資安：S3 DAST 真的去打
S5 把注入樣本餵進真的守衛
不是讀程式碼判斷「應該有擋」

為什麼 C 是這個產品真正的護城河

A 跟 B 是 coverage 工具在做的事的嚴格版。C 才是別人沒有的。 業界的部署後驗證（Argo Rollouts、Flagger、Kayenta、Checkly）看的是指標——error rate、p99 latency。 這裡看的是功能矩陣 + 曝露面矩陣，而且對「這次部署真的發生了嗎」要求一個獨立事實。

IV

資安：同一套公理，第二個座標系

功能會被遺忘，對外監聽的埠、洩進 git 歷史的金鑰、沒有 auth 的 route 也會 —— 而且後者更糟，因為它們沒有使用者會回報。所以資安用完全相同的結構： 自動發現曝露面 → 宣告哪些是刻意的 → 對線上取得證據。

為什麼現在非講不可：兩個獨立的量測

一、量變。2026 年的獨立研究把 AI 產出的程式碼的漏洞率放在 25%–45% 之間（方法學不同）：Veracode 測了 100 多個模型，45% 的樣本引入 OWASP Top 10 缺陷； CodeRabbit 量到 AI 碼引入漏洞的機率是人寫的 1.88 倍。

二、質變，而且這才是重點。agent 本身現在就是攻擊面， 而傳統 SAST / SCA 結構上看不到它 —— 它們讀程式碼，讀不到工具描述、記憶寫入、 agent 之間的流量，而那正是 agentic 攻擊實際發生的地方。

S5 —— 把 agent 的工具清單當成一份 registry

這是整個產品最原創的一步，而且它不是新發明，是把已經成立的公理搬過去： agent 的工具清單有和 feature registry 一模一樣的三個問題，所以有一模一樣的三個答案。

S5.approval 就是 deployProof 換了一套衣服

部署的規則是「不要信回報，去拿證據」。核准的規則是同一句話。

如果人核准的是模型寫的摘要，那他核准的是模型對那個動作的描述，不是那個動作。 檢查方式是機械的：把顯示出去的東西雜湊一次，把實際執行的東西雜湊一次，要求位元組相同。

這對應 OWASP 的 ASI09（Human-Agent Trust Exploitation）， 而 EchoLeak 那封信做的正是這件事 —— 它指示模型絕對不要提起這封信， 所以使用者看到的是一個看起來完全正常的回答。幾乎沒有產品出這條檢查。

兩條讓資安閘門不會被人刪掉的規則

  • 只擋這次改動新增的發現。已知債進 baseline，指紋是 sha256(規則 | 檔案或 URL | 正規化證據) —— 不含行號（會移動）、不含時間戳。 會對已知債擋下每一次部署的閘門，是一個大家會刪掉的閘門。 但已知債會在每份報告裡被點名，而且附上它已經活了幾天。
  • 永遠不印出金鑰本身。證據一律遮罩、baseline 只存指紋， 而且有測試斷言「植入的假金鑰本體不出現在任何一份輸出裡」。 一個會把 secret 寫進 CI log 的資安掃描器，本身就是一場資安事故。

這一層自己差點重演第 II 節那個洞

第一版的資安格是這樣寫的：掃描器沒丟例外就回 pass，把等第放在 detail 字串裡 —— 只是它讀 r.grade 而掃描器報的是 r.summary.grade。 於是 detail 印「ran」，而一個等第 F 印出一列綠的。 跟第 II 節每一個事故同一個形狀：東西執行了，所以看起來沒事。 這就是為什麼 grade() 現在是一個有測試的純函式，而格子斷言的是它的值，不是例外的缺席。

V

AI 開車：指令集、權限分界，與那條不能過的線

前提改變了：跑這些指令的是 AI，不是人。 所以第 1 步（佈線）跟第 2 步（認領）都應該由 AI 自動完成，人只在兩個地方出現—— 給意圖，以及核准消音。

三個步驟，誰做什麼

AI 自動
步驟 1 · WIRE 佈線（一次性）

探查專案：框架、部署形狀、角色與登入方式、監聽埠。產出 adapter 草稿 + 列出所有 orphan。 只有一件事要人確認：proof 怎麼取得——因為這條錯了，整個閘門就失去意義， 而它是唯一 AI 猜錯了也不會有任何東西報錯的欄位。

AI 自動
步驟 2 · ADOPT 認領（每次加功能）

把每個 orphan 補成宣告：area、需要的角色、P0–P2、testId、probes、要不要 journey、 測試檔掛進哪個套件。人可以附加一段自然語言意圖，AI 讀它來決定怎麼填。

確定性
步驟 3 · SHIP

verify → [pre-swap-health] → build → swap → prove → sweep（含 S 層）→ gate → probe → [post-swap acceptance] → report。 判決全部是純函式，沒有一行 LLM。

方括號是專案選擇宣告的 acceptance：pre-swap-health 只能問「相依的東西還活著嗎」（登入、最短的一次請求）， post-swap 才能判斷功能行為，因為換版之前站台還是正在被取代的那一版——在那時候跑功能驗收， 舊版的偶發問題與新版才有的行為都會擋住新版。把功能驗收宣告在換版前，ship 會拒絕（除非明確宣告獨立的 staging 實例）。

那條不能過的線

AI 可以擴大檢查面，不可以移動及格線。

為什麼：寫的跟審的是同一個模型，盲點是相關的。 讓 AI 決定「算不算過」，等於把第 II 節那十個洞一次全部接回來。

而且有一個更陰險的版本：AI 有能力讓閘門閉嘴。 它可以不補宣告，改成把功能丟進 ignored.ts；可以把 route 加進 public-api.ts； 可以 --without 掉紅掉的那層；可以 --update-baseline 把資安發現吃掉。 這四條全是合法的消音管道，所以它們必須是人的。

動作方向誰
寫宣告、寫 probes、寫 journey、把測試掛進套件擴大檢查面AI 自動
寫 adapter 的 build / swap / sessionFor擴大檢查面AI 自動
寫 adapter 的 proof定義什麼叫「成功」AI 提案 · 人確認一次
ignored.ts / public-api.ts 新增一筆縮小檢查面人核准 + 理由
--without 跳過一層縮小檢查面人核准 + 理由
資安 --update-baseline縮小檢查面人核准（等同 code review）
改判決規則（kernel）移動及格線kernel 對 AI 唯讀

指令集

每個指令都有明確的輸入與產物，好讓 AI 可以照著走而不用猜。 --intent 是人可以附加的自然語言，AI 會參考它來填宣告。

─── ① 佈線（一次性，AI 跑）────────────────────────────────
vibeubi init                    探查專案 → 寫出 vibeubi.config.mjs 草稿 + 列出所有 orphan
vibeubi init --confirm-proof    人唯一必須看的一步：「怎麼證明部署生效」

─── ② 認領（每次加功能，AI 主要走這條）──────────────────────
vibeubi add page /settings/billing \
     --intent "企業管理員才看得到；沒有訂閱時儲存鈕要是停用的，不是消失"
     → 建檔 + 補宣告（area / role / P0-P2 / testId）
     → 從 intent 推出 probes：expectDisabled 而不是 expectHidden
     → 判斷要不要 journey（會寫入 → 要）
     → 把新測試檔掛進某個套件（否則 verify 會點名它）

vibeubi orphans                 現在有哪些東西沒人認領（功能 + 曝露面 + 工具）
vibeubi adopt                   把每個 orphan 都補齊
vibeubi adopt --only area=auth
vibeubi intent <id> "…"         事後補意圖；下次 adopt 會重擬 probes

─── 查 ───────────────────────────────────────────────────
vibeubi plan                    印出要做什麼，什麼都不碰
vibeubi why <id>                誰宣告的、上次判決、被誰豁免
vibeubi roster                  agent 的工具面：pin、drift、poison

─── ③ 跑 ─────────────────────────────────────────────────
vibeubi verify                  只跑離線層（含 S0–S2）—— 不建置、不換版
vibeubi scan --base <url>       資安 S0–S7
vibeubi ship                    全流程，含自動回滾
vibeubi rollback                放回上一版，並且證明它
vibeubi viz --format archify    把這次 run 匯出成圖的 IR

─── 需要人（AI 只能提案，執行會停下來）──────────────────────
vibeubi exempt <id> --reason "…"        → ignored
vibeubi public <route> --reason "…"     → publicApi
vibeubi accept-debt --reason "…"        → 資安 baseline

vibeubi guard --action <a>      把上面那條線變成可執行的：
                                   declare / probe / journey / pin → exit 0
                                   ignore / public / without / accept-debt
                                   / unpin / lower-priority          → exit 1

意圖欄位的一條硬規則

--intent 寫進宣告的 intent 欄位，而那個欄位 只有 AI 讀，閘門永遠不讀。閘門只看結構化欄位（priority、requiredRole、 probes、expect）。這樣一來，意圖寫得含糊或過時不會讓判決失準—— 它只會讓下一次 adopt 擬出比較差的 probes，而那是看得見、可以改的。 把自由文字接進判決路徑，就是把不確定性接回閘門裡。

把這次 run 交給任何一個畫圖的 skill

畫圖的 skill 通常是「請 agent 讀 codebase，吐一份 IR」—— agent 用猜的， 而圖正確到跟那個猜測一樣的程度。VibeUbi 不用猜：registry 本身就是 IR。 它是機械發現、明確宣告出來的，而且每個節點已經帶著一次真實 run 的判決。

vibeubi viz --format archify > coverage.archify.json   # 交給 archify，它負責編譯
vibeubi viz --format ir      > coverage.ir.json        # 中性 IR，給任何別的畫圖工具
vibeubi viz --format mermaid > coverage.mmd            # 零相依備援

// 每個節點都帶來源，所以這張圖可以被查核，不是被相信：
{ "id": "page:/settings/billing", "tone": "danger",
  "provenance": { "discoveredIn": "app/settings/billing/page.tsx",
                    "declaredIn": "vibeubi.config.mjs" },
  "coverage": [{ "layer": "L2", "status": "pass" },
               { "layer": "L3", "status": "fail", "reason": "…" }] }

中性 IR 刻意不是 archify 的形狀，所以換一個畫圖 skill 也接得上 —— 多支援一個是寫一個投影函式（toArchify 只有 18 行），不是做一次整合。 圖說裡那句話不能省：「節點是從原始碼樹發現、在 registry 宣告的； 顏色是 run <id> 的判決。這裡沒有任何東西是模型推論出來的。」 那句話就是這張圖跟一張生成圖的全部差別。

裝在任何 harness 上：plugin、skill，還是一支 CLI

「可移植」有兩個方向，兩個都要做到： ① VibeUbi 要能裝進任何 agent harness； ② 任何專案要能被 VibeUbi 接上。

① 裝進 harness —— 三層遞降，沒有一層是必須的

層檔案誰讀得懂

刻意的順序：能讀 skill 的用 skill，不能的讀 AGENTS.md，都不行的就 shell 出去。 沒有任何一層是必要的，所以沒有任何一個 harness 會被鎖在外面。

② 接上專案 —— 外掛長得像 DSH plugin

用的是 DSH／cordis 的形狀，因為那是在每一個宿主裡都成立的最小合約： 只要能 import() 一個檔案，就能載入一個外掛。

export const name = "vibeubi-fastapi"

export function apply(ctx, config = {}) {
  if (!config.root) return              // 沒設定 → 安靜 no-op，絕不丟例外

  ctx.discover("route", async () => [...])    // A · 存在
  ctx.layer("L1",  { run: async (f) => [...] })
  ctx.rule("S5.egress", { run: async () => [...] })
  ctx.target({ proofClaim, proof, build, swap })   // C · 證據
  ctx.session(async (role) => ({ cookie: "…" }))

  ctx.on("dispose", () => {})
}

失敗政策才是重點，不是 API

一個外掛永不向宿主迴圈拋錯，也永不阻塞它。核心把每個外掛提供的函式都包起來： 丟例外 → 那個能力被停用，然後 capabilityCells() 把它變成一個 error 格 —— 而 error 會擋住閘門。

這個組合是刻意的：
一個崩掉的外掛不可以中止一次 run（那會讓工具沒法用）
一個崩掉的外掛也不可以安靜地移除一項檢查（那會讓工具不誠實）

ctx.target 只能被宣告一次。兩個外掛都宣告會是一個點名兩者的載入錯誤， 而不是安靜的「後者覆蓋前者」—— 部署目標決定「證明」是什麼意思，而一個模稜兩可的定義比沒有更糟。

建的時候被自己的規則抓到兩個真 bug

一、毒性樣式原本是把真的碼位貼進原始碼的，而一個 shell heredoc 吃掉了星體平面的字元， 留下 [\u0030-\u0046] —— 一個匹配任何數字的範圍。 地球上每一個乾淨的工具都變成 CRITICAL。現在樣式一律用跳脫寫，而且有一個測試斷言它們不含原始非 ASCII。

二、嚴重度的門檻寫成了 Math.min，讓門檻變成 critical， 於是每一個 HIGH 都被放行。兩個 bug 都由我當場補的回歸測試守住。 這正好是這個專案的論點：「我寫的，所以應該對」不是一種證據。
